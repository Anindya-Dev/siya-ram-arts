# Siya Ram Arts (सिया राम आर्ट्स)

> Premium handcrafted murtis and sacred temple sculptures sculpted by master artisans of Jaipur and Kashi.

Siya Ram Arts is a full-stack luxury spiritual e-commerce platform combining a modern, responsive React frontend with an enterprise FastAPI backend, Supabase PostgreSQL, Clerk authentication, and Razorpay checkout.

---

## Architecture Overview

- **Frontend**: React 19, TypeScript, Vite, TailwindCSS, Motion, Clerk React, Lucide Icons.
- **Backend API**: FastAPI (Python 3.11+), SQLAlchemy 2.0 (AsyncIO), Alembic migrations, Pydantic v2 (camelCase serialization via `BaseResponseSchema`).
- **Database & Storage**: Supabase PostgreSQL 17, Supabase Storage for high-resolution idol media.
- **Authentication**: Clerk (JWT verified via JWKS, RBAC: `customer`, `staff`, `admin`).
- **Payments**: Razorpay (Signature verification, payment webhooks, automatic ledger capture).
- **Invoicing**: GST-compliant invoices generated with WeasyPrint.
- **Logistics**: Shiprocket tracking integration.

---

## Prerequisites

- **Node.js**: `v18.0.0` or higher
- **Python**: `3.11` or higher
- **PostgreSQL**: Supabase PostgreSQL or local PostgreSQL 15+

## Local Development Setup

### 1. Backend Setup (FastAPI)

```bash
# Create and activate Python virtual environment
python -m venv venv
# On Windows PowerShell:
.\venv\Scripts\Activate.ps1
# On Linux / macOS:
# source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Run database migrations
alembic upgrade head

# Seed initial catalog, locations, users, and inventory
python app/db/seed.py

# Start backend dev server (port 8000)
uvicorn app.main:app --reload --port 8000
```

Backend will be accessible at:
- API Root: `http://localhost:8000/api/v1`
- Interactive Swagger Docs: `http://localhost:8000/docs`
- ReDoc Docs: `http://localhost:8000/redoc`

### 2. Frontend Setup (React + Vite)

In a separate terminal:

```bash
# Install dependencies
npm install

# Start Vite dev server (port 3000)
npm run dev
```

The Vite dev server proxies `/api` and `/static` requests to FastAPI on `http://localhost:8000`.
Visit `http://localhost:3000` to interact with the catalog.

## Database Migrations (Alembic)

Migrations manage the PostgreSQL schema.

```bash
# Check current migration status
alembic current

# Apply all pending migrations to HEAD
alembic upgrade head

# Create a new autogenerated migration
alembic revision --autogenerate -m "describe_changes"

# Rollback one migration
alembic downgrade -1
```

## Database Seeding

The seed script ([`app/db/seed.py`](app/db/seed.py)) populates:
- **Locations**: Jaipur Artisan Atelier (`JPR`) and Kashi Sanctum Studio (`KSH`).
- **Staff & Admin Users**: Seed accounts for administrative control.
- **Product Catalog**: 33 canonical handcrafted idols, complete with:
  - 12 canonical specification keys (`canonicalForm`, `primaryMedium`, `ornamentationGrade`, `mudrasAttributes`, `pedestalFoundation`, `archComposition`, `authenticationSeal`, `netWeight`, `heightWidth`, `provenance`, `pratishthaStatus`, `craftsmanshipTime`).
  - Image references formatted as `{ "url": "...", "alt": "...", "isPrimary": true }`.
  - Dimension and material variants with SKU generation.
  - Multi-location stock allocation and stock ledger entries.

To seed or re-seed:

```bash
python app/db/seed.py
```

*Note: Seeding is idempotent. It skips products that already exist by SKU unless force-reseeded.*

## Supabase Storage Setup

1. Log into your [Supabase Dashboard](https://supabase.com/dashboard).
2. Navigate to **Storage** and create a bucket named `idols` (Public).
3. Upload idol photography assets into `idols/`.
4. The public URL structure is:
   ```
   https://<project-ref>.supabase.co/storage/v1/object/public/idols/<filename>.png
   ```
5. Configure `SUPABASE_URL` and `SUPABASE_ANON_KEY` in `.env`.

## Note on WeasyPrint (PDF Invoice Generation)

WeasyPrint requires system C-libraries (`libgobject-2.0-0`, Pango, Cairo):
- **Linux/Docker**: Installed via `apt-get install libpango-1.0-0 libharfbuzz0b libpangoft2-1.0-0 libffi-dev`.
- **Windows**: When running locally without GTK libraries, the application starts cleanly and handles all API traffic; PDF invoice generation logs a graceful fallback warning. For production container builds, Alpine or Debian slim images include these libraries natively.
